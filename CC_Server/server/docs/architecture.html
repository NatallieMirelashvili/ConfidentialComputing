Management Server — Architecture & Walkthrough

The User ↔ Server half of the system: an HTML UI + REST API protected by TLS 1.3 (pluggable transport security — TLS is the only mode implemented today). Sensor data enters through a clean DeviceLink seam, backed by a real edge device over TCP — no synthetic fallback.

1 · Overview & scope

An IoT edge device (emulated with OP-TEE / ARM TrustZone) collects sensor data and sends it to this Management Server, which serves an end user. This codebase implements the user-facing half only.

In scope (built here)

  • HTML UI + REST API
  • A pluggable User↔Server transport-security interface: TLS 1.3 (only mode today)
  • Collect → store → aggregate (weighted average, mean, …)
  • A stable DeviceLink seam, backed by a real edge device
  • Server↔Device remote attestation & encrypted sensor channel (attested_network)

Out of scope

  • The edge device / TA side (OP-TEE, separate part of the project)

Sensor data here comes from AttestedNetworkDeviceLink (or the plaintext NetworkDeviceLink) behind the DeviceLink seam — no synthetic fallback; MS_DEVICE_LINK must select a real link or the server refuses to start.

2 · Architecture

Every request flows through the selected UserChannel (security), into thin FastAPI routes, to the CollectionService (business logic), and only reaches sensor data through the DeviceLink seam.

3 · Transport security

The route handlers only touch one interface (UserChannel), never the crypto itself. TLS 1.3 is the only mode implemented today; adding another (e.g. mutual-TLS, or an app-layer AEAD mode) is a new file under transport/ + one branch in transport/__init__.py — the routes wouldn't change.

6 · Key code walkthrough

One interface, pluggable security modes

class UserChannel(ABC):        # transport/base.py
    def ssl_context(self) -> ssl.SSLContext | None: ...  # TLS returns ctx; app-layer modes None
    def install(self, app): ...   # TLS: no-op; a future mode adds routes/middleware here
    def describe(self) -> dict: ...  # tells the browser which mode is active

The seam — the only way sensor data enters

class DeviceLink(ABC):          # device_link/base.py
    async def collect(self, device_id, window) -> Batch: ...
    def status(self) -> dict: ...
# Batch carries the verdict: attested / integrity / measurement_ok

Recency-weighted average

# processing.py — newer samples weigh more (weight grows with timestamp)
for s in samples:
    w = (s.ts - ts_min) + step
    num += w * s.value ; den += w
return num / den

8 · How to run

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r server/requirements.txt

# TLS 1.3 (default, only mode today)
python -m server.main --security tls       # https://localhost:8000

python -m pytest server/tests -q             # unit + E2E

Security notes. The TLS cert is self-signed → a one-time local browser warning; the context is TLS-1.3-only. All configuration comes from config.Config (MS_* env vars).
